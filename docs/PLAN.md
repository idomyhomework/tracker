# План разработки — ultra-tracker-pro

> Рабочее имя. Финальное название выбираем до публикации в сторах.
> Термины — по [`GLOSSARY.md`](../GLOSSARY.md). Ключевые решения — в [`docs/adr/`](./adr/).
> Сроков нет: этапы идут по порядку, каждый заканчивается рабочим результатом.

## Продукт в одном абзаце

Приложение для самосовершенствования: **Gym** (тренировки), **Diet** (питание) и **Mandala** (план жизненной цели по методу Харады) — это Core Modules. **Habits** и **Notes** — Supporting Modules. Работает без регистрации и офлайн; Account нужен только для синхронизации и платных Plans. Платформы: веб, iOS, Android. Языки с первого дня: EN, ES, RU.

## Что берём из Forge Vault, а что нет

| | Решение |
|---|---|
| Gym | Функции те же, код пишем заново (были баги: потеря Active Workout, таймеры, вес тела) |
| Habits | Переносим идею, переписываем как Supporting Module |
| Notes | Переписываем, добавляем облако с E2E-шифрованием |
| Finances, Ahorros | Удаляем |
| Diet, Mandala | Новые |
| Визуальный стиль | Сохраняем дух (тёмная тема, кислотный акцент, моно-подписи), дизайн-систему собираем заново |
| Данные программ и упражнений | Переносим в `packages/i18n`, переводим |

Подписка месяц/год, trial 7 дней, без рекламы. Цены — ближе к запуску. Единый источник прав — RevenueCat (App Store, Google Play, Stripe на вебе).

## Архитектура

```
apps/
  app/        React + Vite + TS + Tailwind · Dexie · Zustand · i18next · Capacitor
  site/       Astro: лендинг, цены, блог, SEO-страницы (EN/ES/RU, hreflang)
packages/
  domain/     чистая логика без UI: Active Workout, калории, Daily Target, Mandala, sync, crypto
  ui/         дизайн-токены и компоненты
  i18n/       переводы + данные упражнений/программ (общие для app и site)
```

- **Local-first**: все данные сначала в IndexedDB (Dexie); Account опционален.
- **Backend**: Supabase (EU, Франкфурт), доступ только через собственный слой данных ([ADR 0003](./adr/0003-supabase-behind-a-data-layer.md)).
- **Sync**: своя, по записям — `updated_at`, последняя запись побеждает, мягкие удаления.
- **Профили**: Gym и Diet привязаны к Profile, остальное — к Account ([ADR 0005](./adr/0005-gym-and-diet-scoped-to-profile.md)).
- **Active Workout** сохраняется на каждом изменении, таймеры — от сохранённых меток времени ([ADR 0004](./adr/0004-active-workout-persisted-on-every-change.md)).
- **Уведомления**: только локальные (Capacitor Local Notifications), сервер не нужен.
- **Аналитика**: PostHog EU, только события, без содержимого тренировок/еды/заметок, с opt-out.
- **Тесты**: `packages/domain` — через TDD. UI — руками + e2e на ключевые сценарии.

## Этапы

### 1. Фундамент

**Цель:** пустое приложение, на котором можно строить модули.

- Монорепо pnpm workspaces, структура выше; ESLint, Prettier, Vitest.
- `packages/ui`: токены (цвета, шрифты, отступы), базовые компоненты (Button, Input, Modal, Sheet, Tabs), тёмная тема.
- `packages/i18n`: i18next, EN/ES/RU, правило — ни одной строки в коде, только ключи.
- Слой данных: интерфейс репозиториев поверх Dexie (облако подключится в этапе 6 без изменения UI).
- **Owner Profile**: онбординг (пол, возраст, рост, вес, цель), один для Gym и Diet.
- Навигация по Modules, оболочка PWA.

**Готово, когда:** приложение запускается на вебе, переключает языки, хранит Owner Profile в IndexedDB, переживает перезагрузку.

### 2. Gym (переписываем)

**Цель:** то же, что было в Forge Vault, но без багов.

- `packages/domain`: машина состояний Active Workout (подходы, отдых, пропуск, досрочное завершение, выход) — **тесты первыми**.
- Сохранение Active Workout на каждом шаге; восстановление после убийства приложения.
- Таймеры от меток времени (не от тиков).
- Встроенные программы и упражнения — из `packages/i18n`, переведены.
- Конструктор программ (drag & drop), выбор дней недели, расписание.
- Упражнения на время (планка) и с весом тела.
- Калории по MET от Owner Profile.
- История, архив программ, графики прогресса, HIIT.

**Готово, когда:** можно провести тренировку, свернуть приложение на 30 минут, вернуться — и всё на месте. Тесты domain зелёные.

### 3. Mandala

**Цель:** главная отличительная фишка, полностью самостоятельная ([ADR 0002](./adr/0002-mandala-is-standalone.md)).

- Сетка 9×9: **Main Goal** (с **Target Date** и **Why**) → 8 **Sub-goals** → по 8 **Actions**.
- **Action Status**: Not Started / In Progress / Done — ставит пользователь.
- **Deadline** и **Recurrence** на Action: дают напоминания и подсветку, но статус не вычисляют.
- Удобный ввод на телефоне: зум из общей сетки в Sub-goal и обратно.
- Лимит Free: 1 Mandala (сам лимит включаем в этапе 6).

**Готово, когда:** можно заполнить всю мандалу на телефоне, менять статусы, видеть просрочки.

### 4. Diet

**Цель:** дневной учёт калорий и БЖУ.

- `packages/domain`: расчёт **Daily Target** по Profile (Mifflin-St Jeor + цель) — тесты первыми.
- **Food**: поиск по OpenFoodFacts, сканер штрихкодов, свои продукты, своя библиотека блюд.
- **Meal Entry**: порция Food в приёме пищи.
- Дневной баланс: съедено vs Daily Target, с учётом калорий из тренировок Gym того же Profile.
- Кэш найденных продуктов в IndexedDB (офлайн в магазине/кухне).

**Готово, когда:** можно отсканировать продукт, записать порцию и увидеть остаток на день.

### 5. Habits и Notes (локально)

- **Habits**: недельный трекер, история, график регулярности; лимит Free — 5.
- **Notes**: блоки (текст, списки), цвета; пока только на устройстве.

**Готово, когда:** обе вещи работают офлайн на одном устройстве.

### 6. Account, синхронизация, Plans

- Supabase в EU: Auth, Postgres, RLS; схема — чистый Postgres.
- Подключение облачной реализации слоя данных; синхронизация (last-write-wins, мягкие удаления), миграция локальных данных при первом входе.
- RevenueCat: Free / Pro / Coach, trial 7 дней; Stripe для веба.
- Включение лимитов Free.
- **GDPR**: отдельная галочка согласия на обработку данных о здоровье при создании Account; удаление Account и всех данных из приложения; экспорт данных.
- PostHog EU.

**Готово, когда:** купил Pro на вебе → данные и Pro появляются на телефоне; удаление Account стирает всё.

### 7. Notes в облаке с E2E

- Ключ из пароля, шифрование на устройстве, сервер видит только шифротекст ([ADR 0001](./adr/0001-end-to-end-encrypted-notes.md)).
- **Recovery Code** при включении, понятное предупреждение о потере.
- Смена пароля перешифровывает ключ, а не все заметки.
- `packages/domain/crypto` — тесты первыми.

**Готово, когда:** заметка, созданная на телефоне, читается на вебе; в базе — нечитаемый шифротекст.

### 8. Мобильные приложения

- Обёртка Capacitor для iOS и Android.
- Локальные уведомления (Recurrence, Deadline, Habits). iOS — лимит 64 запланированных: планировать только ближайшие при каждом запуске.
- Таймер отдыха в фоне: на Android — foreground-сервис на время Active Workout (точные будильники недоступны); на iOS — уведомление на момент окончания.
- Иконки, сплэш, safe areas, ревью сторов, политика конфиденциальности.
- Финальное название.

**Готово, когда:** приложение опубликовано в App Store и Google Play.

### 9. Распознавание еды по фото (Pro)

- Edge Function → модель для распознавания → предложенные Food и порции, пользователь подтверждает.
- Только для Pro, с лимитами по запросам.

### 10. Coach Mode (Coach Plan)

- Несколько Profiles на Account в Gym и Diet, быстрое переключение.
- Mandala, Habits, Notes не затрагиваются.
- У управляемых Profiles нет своего входа; связи с собственным Account клиента нет.

## Сайт (параллельно, начиная после этапа 3)

- `apps/site` на Astro: лендинг, цены, политика конфиденциальности, блог.
- SEO-страницы на трёх языках, из общих данных `packages/i18n`:
  - библиотека упражнений (страница на каждое упражнение);
  - готовые программы;
  - гайд по Mandala и шаблоны (метод Харады, «мандала Отани») — главная ставка.
- Не делаем: страницы калорийности продуктов.

## Идеи на потом (не в v1)

- Action → «сделать привычкой» (мягкая связь Mandala ↔ Habits) — первая кандидатура.
- Шаблон мандалы «Тело» с готовыми Sub-goals.
- Еженедельный обзор: мандала + статистика Gym/Diet.
- Модель «тренер ↔ клиент» с отдельными Accounts.
- Планы питания как шаблоны.
- Серверные пуши.
- Переезд с Supabase на свой бэкенд при росте.
